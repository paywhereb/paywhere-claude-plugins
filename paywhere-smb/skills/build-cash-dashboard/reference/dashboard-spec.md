# `dashboard/cash.html` — spec

Written by `build-cash-dashboard`; rewritten (same path, same shape) by
`daily-cash-brief`. One file, no network. Data block first so a regeneration
can swap only the JSON.

Field names mirror the answer-key paths the presenter kit references
(`balances`, `trueAvailable`, `tax.shortfall`, `ar.aging`) so a readback is
easy; values always come from the live connectors.

## Rendering

- Inline script reads the JSON, renders each section into a `<main>` with
  one `<section>` per card; if a source is `false`, render the card with a
  single line "Source unavailable" instead of numbers.
- Forecast chart: inline SVG, x = 13 weeks, y = close; polyline for close,
  a dashed horizontal line at `reserveToKeep`, a filled circle + label at
  `minimum`. Table of the same 13 rows underneath.
- Aging: five horizontal CSS bars scaled to `arAging.total`.
- Tax gauge: a single bar `reserveBalance / collectedNotRemitted`; shortfall
  text in red when > 0; missed sweeps as chips.
- Obligations: table sorted by date with running balance starting from
  `trueAvailable.amount`.
- Colors: neutral text, one accent; red only for shortfall, below-reserve
  weeks and 61+ day aging; amber for 31–60 and flagged subscriptions.
- Layout: CSS grid of cards, `max-width: 1100px`, single column below 700px.
  System font stack, `$#,##0` formatting via a small formatter in the script.
- Footer: generatedAt, sources, "Static snapshot — regenerated by
  daily-cash-brief; not financial advice."

## Do not

- Load anything from the network (fonts, chart libraries, CSS).
- Put any value in the HTML that is not also in the JSON block.
- Change field names between runs — the daily brief and the presenter kit
  depend on them.
