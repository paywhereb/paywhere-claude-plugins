# Build Cash Dashboard

Cowork writes files into the owner's working folder; this skill turns the
bank and the books into two of them (a third on request). Data is pulled
once, embedded, and dated. **A static file cannot call MCP** — say so when
delivering: "live" means the file is regenerated by
[`../daily-cash-brief`](../daily-cash-brief/SKILL.md) each morning (same path,
same shape), or the owner asks for a refresh. Nothing here stages money or
writes to the books.

**Progress tracking:** call `TaskCreate` once per step below before starting
Step 1 (subject = the step's name, e.g. "Step 1 — Pull the data"), then
`TaskUpdate` it to `in_progress` when you begin that step and `completed`
when it's done. This is what drives Cowork's visible progress display — it
does not happen unless you do it explicitly.

## Step 1 — Pull the data (by reference, once)

Do not re-derive methods here; run the sibling skills' data steps and keep
their results:

| Data | Method |
|---|---|
| Balances by role, pending, true available | [`../business-pulse`](../business-pulse/SKILL.md) Steps 1–2 (`reference/true-available.md`) |
| 13-week forecast, minimum, reserve to keep, 12-month history | [`../cash-flow-snapshot`](../cash-flow-snapshot/SKILL.md) Steps 1–4 |
| AR aging, top overdue, payer profiles | [`../ar-health`](../ar-health/SKILL.md) |
| Next-30-days obligations (bills at due date, payroll pattern, Calendar events with amounts) | cash-flow-snapshot Step 3 |
| Reserve balance, collected-not-remitted, shortfall, next remittance, missed sweeps | [`../tax-reserve-check`](../tax-reserve-check/SKILL.md) |
| Subscriptions with flags | [`../subscription-audit`](../subscription-audit/SKILL.md) |
| Needs-you items | business-pulse Step 3 candidates (all, ranked) |

Resolve "today" from the actual date. A missing connector removes a card
and is named in the footer; never invent a value.

## Step 2 — `dashboard/cash.html` (one file, offline)

Rules: one HTML file, **no external scripts, stylesheets or fonts**; charts
as inline SVG or CSS bars; all data in one `<script id="data"
type="application/json">` block near the top so a refresh replaces only that
block; a small inline script renders it. Mobile-friendly (single column
under ~700px), light styling, system font, dollar amounts rounded, red/amber
only where a threshold is crossed. Section order and the JSON shape are in
[`reference/dashboard-spec.md`](reference/dashboard-spec.md). Sections:

1. Header — business name (books), "Generated {timestamp}", sources used.
2. Balance tiles — Operating · Tax Reserve · Business Savings · Pending, and
   the **True available** tile showing its formula with numbers.
3. 13-week forecast chart — closing-balance line, the minimum week marked,
   the reserve-to-keep line; table beneath for the numbers.
4. Receivables — aging bars (current / 1–30 / 31–60 / 61–90 / 90+) and the
   top overdue table (customer, amount, days late, usual behavior).
5. Next 30 days — dated list of obligations with source (books / bank /
   calendar) and a running balance.
6. Tax reserve gauge — reserve balance vs collected-not-remitted; shortfall
   in red; next remittance date; missed sweep Fridays.
7. Subscriptions — vendor, monthly, months seen, flag (zero-attribution,
   orphaned, duplicate).
8. Needs you — ranked list with the skill to run for each.
9. Footer — "Static snapshot; regenerated by the daily cash brief. Not
   financial advice."

## Step 3 — `models/cash-13w.xlsx` (formula-driven)

Write it exactly per
[`../cash-flow-snapshot/reference/model-layout.md`](../cash-flow-snapshot/reference/model-layout.md)
(do not improvise the layout). Non-negotiable: the yellow `Inputs` cells —
collections speed (days), pay-on-due toggle, revenue %, new-hire monthly
cost, purchase payment + cash outlay + start week, LOC limit — are **inputs**,
and every `Forecast` cell is a **formula** that references them, so changing
an input recomputes the minimum. Use Cowork's file tooling; no assumption
about a library. Populate `Levers` from [`../what-if`](../what-if/SKILL.md) if
it ran this session, else leave the header row with a note.

## Step 4 — `tracking/collections.xlsx` (only if asked)

Sheets: `Tracker` — `Customer · Invoice · Amount open · Due · Days late ·
Profile (prompt / routinely late / occasionally very late / delinquent /
retainage) · Last contact · Promise date · Promised amount · Next action ·
Owner`; `Profiles` — one row per customer with mean days late and invoices
observed (from ar-health); `Log` — date · customer · note. Data rows from
ar-health; blank promise/next-action columns for the owner to fill. Drafting
reminders belongs to [`../invoice-chase`](../invoice-chase/SKILL.md).

## Step 5 — Deliver

List the file paths, the generated-at time, which connectors answered, and
the one sentence about refresh: "This is a snapshot — schedule
`daily-cash-brief` (weekdays 7:30) and this file is rewritten every morning
with the same layout." Offer that schedule once.

## Degraded modes

| Missing | Effect |
|---|---|
| Paywhere | Stop — a cash dashboard without the bank is a books report; offer `quarterly-review` instead. |
| quickbooks | Cards 4 and 6 (shortfall) show "QuickBooks unavailable"; forecast inflows are seasonal only. |
| google calendar | Card 5 uses bills + payroll only; footer says so. |
